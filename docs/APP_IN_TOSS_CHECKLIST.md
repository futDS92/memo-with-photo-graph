# App in Toss Checklist

## 1. 플랫폼 적합성

- 미니앱이 토스앱 안에서 정상적으로 열리는지 확인
- 토스앱 테스트용 앱스킴으로 QA 완료
- 출시 전 검수 가이드와 체크리스트 확인
- 현재 프로젝트가 AIT 앱 구조인지 확인
- 정적 HTML 배포가 아니라 App in Toss용 번들로 빌드되는지 확인
- 새 프로젝트는 `npx create-ait-app <app-name>` 기준으로 시작

## 2. 네비게이션

- 토스의 비게임 네비게이션 바 규칙 준수
- 좌측 뒤로가기 동작 확인
- 최초 화면 뒤로가기는 미니앱 종료로 동작하는지 확인
- 자체 뒤로가기 버튼과 토스 기본 뒤로가기 버튼이 중복되지 않는지 확인
- 공유 링크는 토스 앱 내부 딥링크 규칙에 맞는지 확인

## 3. 앱 정보

- 앱 이름이 서비스 성격을 바로 이해할 수 있게 설정
- 브랜드 로고와 국문 미니앱 이름이 노출되는지 확인
- 노출 정보, 설명 문구, 스킴 등록이 일치하는지 확인
- 앱 이름은 `memo with photo graph`로 통일

## 4. 빌드와 용량

- 앱 번들 압축 해제 기준 100MB 이하 유지
- 이미지/사운드/영상 리소스 분리 관리
- 출시용 번들과 테스트용 번들을 분리 가능하게 준비
- 사진은 원본 업로드보다 압축/크롭 후 저장
- 대용량 사진은 로컬 data URL 대신 외부 스토리지 활용 검토
- 최종 산출물은 `npm run build`로 생성된 `.ait` 파일인지 확인

## 5. TDS / 프레임워크

- TDS Mobile 또는 WebView 대응 방식 확인
- React Native라면 `TDSMobileAITProvider` 설정 확인
- 앱 생성은 `create-ait-app` 기준으로 시작하는지 확인
- 토스 앱 버전 확인이 필요한 기능은 `getTossAppVersion`으로 분기

## 6. 기능 검수

- 단어 추가, 편집, 삭제 동작 확인
- 사진 첨부와 교체 동작 확인
- 관계 생성 및 맵 반영 확인
- 검색, 필터, 상세 시트, 내보내기 확인
- 공유 링크/OG 이미지 미리보기 확인

## 7. 보안/운영

- 개인정보 저장 범위 점검
- 업로드 파일 타입 제한
- 서버 저장 API의 인증 여부 확인
- 에러 발생 시 fallback UI 확인

## 8. Toss 스타일

- 화이트 베이스, 낮은 대비, 블루 포인트 유지
- 토스형 카드, 버튼, 입력, 시트 규격 점검
- 커스텀 뒤로가기/닫기 UI 중복 제거
- 접근성 대비 및 터치 타겟 크기 확인

## 9. 배포 전 최종 확인

- 앱 아이콘, 이름, 설명, 진입 경로 일치
- 개발/테스트/운영 환경 변수 구분
- 네트워크 실패 시 안내 화면 존재
- 분석 이벤트와 사용자 동작 로깅 확인
