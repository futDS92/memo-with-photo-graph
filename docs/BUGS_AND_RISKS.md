# Bugs and Risks

## High Priority

1. `server.mjs`는 현재 로컬 개발용입니다.
   - App in Toss 배포용 번들로는 그대로 쓸 수 없습니다.
   - 운영 배포용은 Toss가 요구하는 번들/SDK 방식으로 맞춰야 합니다.

2. `localStorage`와 서버 JSON을 동시에 쓰는 구조는 충돌 가능성이 있습니다.
   - 현재는 서버 응답이 우선이지만, 다중 기기 동기화는 별도 충돌 정책이 필요합니다.
   - 마지막 수정 시각 또는 버전 필드가 없습니다.

3. 사진을 `data:` URL로 저장합니다.
   - 작은 데이터에는 편하지만 용량이 빨리 커집니다.
   - App in Toss 번들 용량 정책과 충돌할 수 있습니다.

## Medium Priority

1. 관계선 레이아웃이 현재는 고정 반경 기반입니다.
   - 노드가 많아지면 겹침이 생길 수 있습니다.
   - 드래그 기반 재배치나 force layout이 필요합니다.

2. 삭제 시 관계도 함께 지우지만 복구가 없습니다.
   - 휴지통 또는 soft delete가 있으면 안전합니다.

3. 서버 저장이 단일 JSON 파일입니다.
   - 동시 쓰기, 백업, 롤백, 감사 로그에 약합니다.

4. 초기 시드 데이터가 앱 코드와 서버 코드에 중복됩니다.
   - 유지보수 시 불일치가 생길 수 있습니다.

## Low Priority

1. `confirm()`과 브라우저 기본 다이얼로그가 섞여 있습니다.
   - Toss 스타일과 완전히 맞추려면 커스텀 모달로 바꾸는 게 좋습니다.

2. 맵 텍스트 라벨은 노드 수가 증가하면 시각적으로 복잡해집니다.
   - 축약 표시 또는 hover/focus 노출이 더 낫습니다.
